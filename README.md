# Тойға — умный подбор подрядчиков

Помогаем организатору мероприятия выбрать подрядчика из каталога своего города. Пользователь указывает дату, формат события, категорию и бюджет; система исключает неподходящих, ранжирует оставшихся и возвращает до трёх карточек с конкретными объяснениями.

Проект команды **unsupervised** для HackAlem, кейс «Умный подбор подрядчиков». Репозиторий: [BAITC-Hacks/hack-03a47d56-unsupervised](https://github.com/BAITC-Hacks/hack-03a47d56-unsupervised).

## Что уже работает

В `main` доступны загрузка CSV, строгая фильтрация, ранжирование, объяснения, CLI и автоматические тесты. Ядро работает на **Python 3.10+ без установки сторонних библиотек**. Для офлайн-запуска API-ключ не нужен.

| Компонент | Состояние |
| --- | --- |
| Каталог из 66 профилей | В репозитории, `contractors.csv` |
| Фильтры и календарь | Реализованы |
| Top-3 и объяснения | Реализованы в модуле ranking |
| AI-сравнение описаний | Эмбеддинги OpenAI при наличии ключа |
| Резервный подбор без API | Офлайн-сравнение по словам |
| Веб-интерфейс | Локальный сайт с формой, примерами, карточками и объяснением первого места |
| Streamlit-дизайн «Тойға» | Отдельное превью команды; основной сайт работает без Streamlit |
| Публичный сайт | Развёртывание пока не выполнено |

**Быстрый путь:** скачайте репозиторий → откройте его корень → запустите тесты → выполните `python web_preview_server.py` и откройте `http://127.0.0.1:8765`. Инструкции ниже рассчитаны в первую очередь на Windows и PowerShell в VS Code.

## 4. Параметры и результат

| Параметр CLI | Обязательный | Пример и смысл |
| --- | --- | --- |
| `--city` | Да | `Алматы`, `Астана`, `Зарубежье` |
| `--date` | Да | `2026-10-01`, дата в формате YYYY-MM-DD |
| `--event-type` | Да | `свадьба`, `той`, `корпоратив`, `конференция`, `юбилей`, `"день рождения"` |
| `--category` | Да | `Ведущий`, `Флорист`, `"Банкетный зал"` |
| `--budget` | Да | `1000000`, тенге за мероприятие |
| `--language` | Нет | `русский`, `казахский`, `английский` |
| `--duration-hours` | Нет | `6`, положительное число часов |
| `--preferences` | Только ranking, нет | `"спокойный стиль и юмор"`, до 2000 символов |
| `--csv` | Нет | Путь к другому CSV в том же формате |
| `--offline` | Только ranking, нет | Работать без внешнего API |
| `--require-ai` | Только ranking, нет | Считать fallback неуспехом AI-проверки |
| `--warm-cache` | Только ranking, нет | Заранее получить эмбеддинги описаний каталога |

Значения с пробелами заключайте в кавычки. Не указывайте необязательное ограничение, если оно не важно. В CLI длительность `0` недопустима; в веб-форме оставьте поле длительности пустым.

### Три исхода

| `status` | Что произошло | Что показать пользователю |
| --- | --- | --- |
| `matched` | Есть подходящие профили | Карточки, объяснения, предупреждения и сообщение о количестве |
| `no_category_in_city` | В городе нет такой категории | Понятное сообщение об отсутствии категории |
| `no_matches` | Категория есть, но условия никто не прошёл | Причины: занятость, бюджет, формат, язык или длительность |

Неправильный ввод — отдельная ошибка, а не пустой поиск. CLI возвращает `status: error` в stderr и код завершения 2. Валидный пустой результат возвращает код 0. У `--require-ai` код 3 означает, что карточки есть, но вместо AI использован fallback. Если кандидатов нет, API не требуется и код 3 не возникает.

### Строгие правила

- Дата должна находиться в известном окне календаря: **23.09.2026–31.12.2026 включительно**. За пределами окна доступность неизвестна.
- Кандидат с выбранной датой в `busy_dates` исключается. Площадки проверяются так же, как люди.
- Цена «от» должна быть не выше бюджета; равенство допустимо. Это не обещание окончательной стоимости.
- Формат мероприятия обязателен. Язык и длительность проверяются, только если заданы.
- Пустой `max_hours` означает работу без привязки к присутствию. Такой профиль не отсекается по длительности.
- Категория сравнивается с отдельным элементом списка, а не с подстрокой.
- Условия автоматически не ослабляются. Для одного исключённого профиля сохраняются все причины, поэтому сумма счётчиков причин может превышать число исключённых.

Полная спецификация — [FILTERING.md](FILTERING.md).

## 6. AI и ключ API

AI сравнивает пожелания пользователя с `description` уже допустимых кандидатов через эмбеддинги. По умолчанию проект настроен на `text-embedding-3-small`; модель задаётся переменной `OPENAI_EMBEDDING_MODEL`. Строгие условия проверяются до AI.

Объяснения собираются из полей CSV и фрагмента описания детерминированно. Они не являются свободно сгенерированным ответом чат-модели.

### Задать ключ только в текущем терминале

Следующий вариант работает в Windows PowerShell с защищённым вводом. Вставьте ключ в запрос ввода, а не в текст команды:

```powershell
$apiKey = Read-Host "OpenAI API key" -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new("", $apiKey).Password
$apiKey.Dispose()
Remove-Variable apiKey
```

Затем выполните:

```powershell
python demo_ranking.py --require-ai --city Алматы --date 2026-09-23 --event-type свадьба --category Ведущий --budget 2000000 --preferences "спокойный стиль и интеллигентный юмор"
```

Проверяйте `ai.mode`: `openai` означает, что использовались эмбеддинги OpenAI, `lexical` — резервное сравнение по словам. Сохранённый AI-результат может быть получен из кэша без нового сетевого вызова. Для подробностей см. [RANKING.md](RANKING.md) и отчёт команды [LIVE_CHECK.md](LIVE_CHECK.md).

После завершения можно убрать ключ из окружения терминала:

```powershell
Remove-Item Env:OPENAI_API_KEY
```

Ядро и CLI читают ключ из переменной окружения. Локальный веб-сервер также читает `OPENAI_API_KEY` из файла `.env` в корне проекта при каждом запросе. Этот файл исключён из Git; настоящий ключ не должен попадать в README, CSV, коммиты или скриншоты.

### Кэш и повторяемость

Эмбеддинги сохраняются в `.cache/embeddings.sqlite3`, результаты CLI — в `.cache/ranking.sqlite3`, а результаты веб-интерфейса — в `.cache/web_preview_rankings.sqlite3`. При неизменных данных, настройках и сохранённом кэше повторный запрос сохраняет порядок даже после перезапуска. Резервный результат тоже фиксируется: восстановление сети само по себе не пересортировывает уже показанную выдачу.

Для подготовки перед AI-демо добавьте `--warm-cache` к команде с `--require-ai`. Это заранее обрабатывает описания каталога. `--offline` нельзя совмещать с `--require-ai` или `--warm-cache`.

При отсутствии ключа или сбое API обычный режим может перейти на лексическое сравнение; фактический режим отражается в `ai`. Если дисковый кэш недоступен для записи, возможна работа с кэшем процесса, но сохранение между перезапусками не гарантируется.

## 7. Веб-интерфейс

В `main` есть локальный сайт на HTML/CSS/JavaScript с сервером на стандартной библиотеке Python. Сайт использует общий `contractors.csv` и действительный пайплайн `filter_contractors()` → `recommend_from_filtered()`; устанавливать Streamlit не нужно.

Из корня проекта выполните:

```powershell
python web_preview_server.py
```

Откройте `http://127.0.0.1:8765` на этом же компьютере. Остановка сервера — `Ctrl+C`. Сайт принимает город, дату, тип мероприятия, категорию и бюджет; дополнительно можно указать язык, длительность и текст пожеланий. Шесть готовых сценариев покрывают плотную и редкую категории, два пустых исхода и смену выдачи при изменении даты.

Результат содержит до трёх карточек, причины исключения остальных и фактический режим сравнения: `OpenAI` либо сравнение по словам. Над карточками показано, почему первый кандидат опередил второго: итоговые и составляющие баллы, формула, проверенные поля каталога и фрагмент исходного описания. Синтетические профили и заполненные при подготовке данные помечены.

Чтобы включить OpenAI в веб-интерфейсе, создайте `.env` в корне проекта:

```text
OPENAI_API_KEY=ваш_новый_ключ
```

Сервер подхватит изменение при следующем запросе; обновите страницу, чтобы обновилась подпись в шапке. Переменная окружения `OPENAI_API_KEY`, если задана, имеет приоритет над `.env`. Проверяйте режим в ответе на **новый** текст пожеланий: ранее сохранённый результат может прийти из кэша. Файл `.env` игнорируется Git и не отправляется в репозиторий.

Точка входа — `web_preview_server.py`, статические файлы — `web_preview/`. Сервер слушает только `127.0.0.1` по умолчанию. `git push` публикует исходники в GitHub, но не развёртывает публичный сайт.

### Подключение UI

```python
from data_loader import load_contractors
from filtering import filter_contractors
from recommendations import recommend_from_filtered
from scorer import RankingEngine

catalog = load_contractors()
engine = RankingEngine(mode="offline")  # Для AI: RankingEngine()

request = {
    "city": "Алматы",
    "date": "2026-09-23",
    "event_type": "свадьба",
    "category": "Ведущий",
    "budget": 2_000_000,
}
filtered = filter_contractors(catalog, request)
result = recommend_from_filtered(
    filtered,
    preferences="интеллигентный юмор",  # Передаётся отдельно от фильтра
    engine=engine,
)

print(result["message"])
for card in result["cards"]:
    print(card["name"], card["price_from_kzt"], card["explanation"])
```

Каталог и `engine` переиспользуются между запросами. Эта цепочка подключена в `web_preview_server.py`; UI показывает `message`, `cards`, предупреждения о происхождении данных и фактический режим `ai`. Не обрезайте `filtered["candidates"]` до трёх перед ranking.

### Как считается score

```text
semantic = max(0, cosine(query_embedding, description_embedding))
budget_headroom = 1 - price_from_kzt / budget
score = 70 × semantic + 30 × budget_headroom
порядок = (-score, id)
```

В офлайн-режиме смысловой компонент заменяется лексическим сравнением. Для нулевого бюджета бесплатному кандидату задаётся запас бюджета 1. Балл округляется до шести знаков; равенство разрешается по `id`. Веса 70/30 — эвристика MVP, а score не является вероятностью успеха или оценкой качества подрядчика.

### Данные и ограничения

В каталоге 66 профилей: 13 помечены `synthetic`, у части заполнены город или цена (`city_imputed`, `price_imputed`). Эти флаги нужно показывать, а не скрывать. Синтетические записи входят в выданный датасет. У 9 профилей `max_hours` не задан.

Проект рекомендует подрядчиков, но не бронирует их, не отправляет заявки и не подтверждает реальную доступность вне исходного календаря. «Свободен» в демо означает отсутствие даты в `busy_dates` датасета.

## 9. Как отправить изменения в GitHub

### Что означают команды

| Действие | Что оно делает |
| --- | --- |
| `git pull` | Получает изменения команды |
| `git add` | Выбирает файлы для следующего коммита |
| `git commit` | Сохраняет выбранные изменения локально |
| `git push` | Отправляет коммиты в GitHub |
| Pull Request | Предлагает объединить рабочую ветку с `main` |
| Merge | Добавляет изменения PR в общую ветку |

### Пример: отправить новый README

Откройте терминал **в клонированном репозитории**, а не в папке ZIP или локального превью. Сначала выполните `git status`: при несохранённых изменениях сохраните их в текущей рабочей ветке перед переключением.

При чистом рабочем дереве:

```powershell
git switch main
git pull --ff-only origin main
git switch -c docs/readme-guide
```

Создавать `docs/readme-guide` нужно один раз. Если такая ветка уже существует локально, переключитесь командой `git switch docs/readme-guide`.

Теперь замените `README.md` в корне проекта новым файлом и проверьте изменения:

```powershell
git status
git diff -- README.md
git add README.md
git diff --cached --check
git diff --cached --stat
git diff --cached
git commit -m "docs: add setup, demo and contribution guide"
git push -u origin docs/readme-guide
```

Откройте репозиторий на GitHub → **Compare & pull request**. Проверьте направление: **base: main**, **compare: docs/readme-guide**. Укажите, что изменено и как проверено, затем создайте Pull Request. Ответственный за интеграцию проверяет изменения и выполняет Merge.

Для следующих коммитов в этой же ветке достаточно `git push`: `-u` уже установил связь с удалённой веткой.

### Пример: отправить изменение кода

Работайте в согласованной ветке своей задачи. Выбирайте только действительно изменённые файлы; имена ниже — пример для модуля фильтрации:

```powershell
python -m unittest discover -v
git status
git diff
git add filtering.py test_filtering.py
git diff --cached --check
git diff --cached
git commit -m "fix: clarify filtering diagnostics"
git push
```

Если это первый push новой ветки, используйте `git push -u origin ИМЯ_ВЕТКИ`, заменив `ИМЯ_ВЕТКИ` на её настоящее название. Не вставляйте этот шаблон буквально.

### Подтянуть main в свою ветку

Находясь в своей ветке с чистым рабочим деревом:

```powershell
git fetch origin
git merge origin/main
python -m unittest discover -v
git push
```

Если есть конфликт, выполните `git status`, откройте указанные файлы и согласуйте итог с автором соседнего изменения. После разрешения уберите маркеры `<<<<<<<`, `=======`, `>>>>>>>`, добавьте исправленные файлы через `git add`, создайте merge-коммит и повторите тесты. Если нужно отменить именно незавершённый merge, используйте `git merge --abort`.

Не применяйте `push --force` или `reset --hard` как способ исправить непонятную ошибку синхронизации. Они не нужны для обычного командного процесса.

### Проверка перед push

Просмотрите `git diff --cached` целиком. В коммит не должны попасть настоящие `.env`, `.streamlit/secrets.toml`, API-ключи, локальные кэши и виртуальное окружение. `.gitignore` не убирает файл, если его уже отслеживает Git.

Если случайно добавили ненужный файл только в staging, уберите его оттуда командой `git restore --staged ПУТЬ_К_ФАЙЛУ` — содержимое на диске сохранится. Если настоящий ключ уже опубликован, сначала отзовите его у провайдера; удаление строки новым коммитом не стирает её из истории.

### После объединения

Остальные участники получают результат в своих клонах:

```powershell
git switch main
git pull --ff-only origin main
python -m unittest discover -v
```

В `main` объединяет один ответственный участник. Наличие кода в GitHub не заменяет запуск тестов и общего демо после интеграции.

## 10. Частые ошибки

| Что видно | Что проверить |
| --- | --- |
| `No module named test_filtering` | Терминал открыт не в папке с `test_filtering.py`; выполните `Get-Location` и `Get-ChildItem`, затем перейдите в корень проекта |
| `Ran 0 tests` | Запущено из неверной папки; это не подтверждение работоспособности |
| `can't open file ... demo_ranking.py` | Неверная папка либо старая копия; в клоне обновите `main` |
| `python is not recognized` | Попробуйте `py -3`, проверьте установку и PATH |
| `not a git repository` | Это ZIP, превью или родительская папка; перейдите в настоящий клон |
| GitHub показывает 404 / `Repository not found` | Репозиторий приватный; проверьте аккаунт, приглашение в команду и точность URL |
| Git запрашивает имя автора | Настройте `git config user.name "Ваше имя"` и `git config user.email "Ваш email GitHub"` в репозитории |
| Push отклонён как `non-fast-forward` | В удалённой ветке есть новые коммиты; получите их и согласуйте merge, не используйте force |
| `git pull --ff-only` сообщает о расхождении | Локальная и удалённая ветки разошлись; проверьте `git status` и историю, сохраните свою работу и согласуйте объединение |
| Создан `.env`, но AI не включается | CLI читает переменную окружения; веб-сервер читает `.env`. Проверьте расположение файла, ключ, сеть и фактический режим в результате |
| `ai.mode` равен `lexical` | Включён offline, нет ключа, был сбой API либо использован сохранённый fallback; смотрите `ai.message` |
| «Доступность известна только…» | Дата должна быть между 2026-09-23 и 2026-12-31 |
| Поиск вернул 0–2 карточки | Это допустимый результат; прочитайте `message` и причины исключения |
| `127.0.0.1:8765` не открывается | Запустите `python web_preview_server.py` из корня проекта; если порт занят, укажите `--port 8766` и откройте новый адрес |

Если ошибка осталась, передайте команде **полную команду, текущую папку и полный текст ошибки**, а не только последнюю строку `FAILED`. Секреты из вывода предварительно удалите.
