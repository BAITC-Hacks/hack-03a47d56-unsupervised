# Проверка OpenAI API и ранжирования

Проверка выполнена 23 сентября 2026 на исходном каталоге из 66 профилей. Обе модели реально вызваны через `https://api.openai.com/v1/embeddings`: `text-embedding-3-small` и `text-embedding-3-large`. Использованы анонимизированные описания и тестовые пожелания с разрешения владельца проекта. Ключ передавался скрытым вводом только в память процесса.

## Выбранная модель

По умолчанию остаётся **text-embedding-3-small**. В проверенных сценариях обе модели работали корректно, заметного практического преимущества large для этого демо не установлено. Small дешевле, а эмбеддинги всего каталога кэшируются заранее. Это инженерный выбор для MVP, а не результат полноценной оценки качества на размеченной выборке.

По официальной документации цена стандартного вызова small — $0.02 за миллион входных токенов, large — $0.13. Large позиционируется как более сильная модель, в том числе для неанглийских текстов. [Small](https://developers.openai.com/api/docs/models/text-embedding-3-small), [large](https://developers.openai.com/api/docs/models/text-embedding-3-large).

## Наблюдаемые результаты

Время ниже измерено для вызова адаптера рекомендаций на этом компьютере и подключении. Оно не является обещанием задержки на другом хостинге. Первый отдельный запрос для проверки соединения занял 2.788 с у small и 0.410 с у large; это последовательные, не сопоставимые по прогреву измерения.

| Сценарий | Результат | Small, с | Large, с |
| --- | --- | ---: | ---: |
| Алматы, ведущий, 23.09, спокойная подача | 3 карточки из 4 допустимых | 1.291 | 0.619 |
| Тот же запрос, пожелание про КВН | 3 карточки; смысловые баллы меняются | 0.329 | 0.377 |
| Алматы, флорист, 04.10 | 2 карточки и объяснение нехватки | 0.398 | 0.494 |
| Алматы, ведущий, 01.10 | 2 карточки | 0.338 | 0.359 |
| Тот же запрос на 02.10 | 1 другой подрядчик | 0.364 | 0.391 |
| Алматы, банкетный зал, 14.11 | 2 карточки | 0.395 | 0.503 |
| Бюджет 1 ₸ | `no_matches`, без API | <0.001 | <0.001 |
| Зарубежье, флорист | `no_category_in_city`, без API | <0.001 | <0.001 |

В шести непустых сценариях подтверждён `ai.mode=openai`. Повторные ответы совпали полностью; время повторного вызова — до 0.002 с. Занятые и превышающие бюджет профили отсутствовали в карточках. Цитаты сверены с исходными описаниями. Повторное создание ранжировщика с тем же кэшем и пустым ключом сохранило результат без сетевых запросов. Векторы всех 66 описаний подготовлены для обеих моделей и остаются только в игнорируемом локальном `.cache`.

## Исправления по итогам проверки

- При ошибке в одном из векторов после частичного расчёта сбрасывается весь набор AI-баллов и заново выполняется текстовое сравнение. Версия кэша ранжирования повышена, чтобы старые смешанные результаты не использовались.
- Подписи вроде «С уважением» и контактные фразы исключаются перед выбором фактической цитаты. Для проверенного ведущего теперь используется фрагмент «Импровизация, живой интеллигентный юмор».

Обе ошибки закреплены регрессионными тестами. Повторяемая локальная проверка: `python -m unittest discover -s tests -v`. Для отдельной живой проверки с собственным ключом используйте команды из [Ранжирование](ranking.md) и флаг `--require-ai`.
