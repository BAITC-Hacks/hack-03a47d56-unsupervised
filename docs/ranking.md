# Ранжирование, AI и объяснения

Модули пакета `app` работают на Python 3.10+ со стандартной библиотекой. Основа — [контракт фильтрации](filtering.md). Установка сторонних пакетов не требуется. Общий порядок запуска описан в [README](../README.md).

[Результаты живой проверки OpenAI и сравнения моделей](live-check.md): проверены все обязательные сценарии, повторяемость и работа с кэшем.

## Где применяется AI

OpenAI `text-embedding-3-small` преобразует запрос и описания подрядчиков в векторы. Косинусное сходство даёт смысловую составляющую ранжирования. Пожелание «спокойная подача и лёгкий юмор» сравнивается с полным `description` каждого допустимого подрядчика. Модель и ключ настраиваются через `OPENAI_EMBEDDING_MODEL` и `OPENAI_API_KEY`.

Реализован настоящий вызов `POST https://api.openai.com/v1/embeddings`, `encoding_format=float`. Описания и запросы отправляются одним пакетом, если их ещё нет в локальном кэше. [Официальный контракт OpenAI](https://developers.openai.com/api/docs/guides/embeddings).

Проверка даты, города, категории, бюджета, языка и длительности выполняется до обращения к AI. Пустой результат не вызывает API; исключение — явно запрошенная CLI-подготовка `--warm-cache`, которая обрабатывает весь каталог перед подбором. Доступность, цену и характеристики для объяснения берём из профиля. Текст объяснения собирается детерминированно из этих фактов и дословного фрагмента описания.

При выборе фрагмента пропускаются самостоятельные представления имени, профессии или названия группы, приветствия и контакты. При наличии содержательных деталей цитируется стиль работы, опыт, языки или другие особенности. Если дополнительных деталей нет, объяснение сообщает об этом. Без пожеланий смысловое сравнение относится к категории и формату события.

## Быстрый запуск

Из корня проекта с `main.py` в PowerShell 7 задайте ключ в текущем процессе (ввод скрыт):

```powershell
$env:OPENAI_API_KEY = Read-Host "OpenAI API key" -MaskInput
python main.py recommend --city Алматы --date 2026-09-23 --event-type свадьба --category Ведущий --budget 2000000 --preferences "спокойный стиль и интеллигентный юмор" --require-ai
```

Корневая `.env.example` перечисляет переменные. CLI читает настройки из окружения и не загружает `.env`. Локальный сервер `python main.py` также читает `OPENAI_API_KEY` из корневого `.env`, если непустой ключ не был передан через окружение при запуске. Модель `OPENAI_EMBEDDING_MODEL` и в CLI, и на сайте читается только из окружения. Ключ не включается в результат, журнал ошибок, кэш или Git.

Для первого запуска перед демо добавьте `--warm-cache`: команда заранее получит векторы всех описаний в каталоге, затем выполнит запрос. Подготовка не входит во время ответа пользовательского запроса. Если ключа пока нет, тот же сценарий можно проверить с `--offline` вместо `--require-ai`.

Обычный режим допускает fallback, возвращает код 0 и явно сообщает `ai.mode=lexical`, если API не ответил. `--require-ai` возвращает код 3, когда есть карточки, но AI не использован. Ошибка ввода, CSV или принудительной подготовки кэша возвращает код 2 и JSON в stderr. Успешный режим AI — `ai.mode=openai`. `score` не является процентом качества или вероятностью успеха.

## Подключение к другому интерфейсу

Серверная логика находится в пакете `app`, обработчики консольных команд — в `app/cli`. Импортируйте модули из корня проекта:

```python
from app.data_loader import load_contractors
from app.filtering import filter_contractors
from app.recommendations import recommend_from_filtered
from app.scorer import RankingEngine

catalog = load_contractors()                 # один раз при старте приложения
engine = RankingEngine()                     # переиспользовать между запросами

request = {
    "city": "Алматы",
    "date": "2026-09-23",
    "event_type": "свадьба",
    "category": "Ведущий",
    "budget": 2_000_000,
    "preferences": "спокойный стиль и интеллигентный юмор",
}
filtered = filter_contractors(catalog, request)
result = recommend_from_filtered(
    filtered,
    preferences=request.get("preferences"),  # обязательно передать отдельно!
    engine=engine,
)
```

`app.filtering.validate_request` сохраняет семь штатных полей и пропускает `preferences`. Адаптер принимает пожелания отдельно и добавляет их в итоговый `request`. Максимум — 2000 символов. Пустая строка допустима: вектор запроса тогда строится по категории и формату.

Сохраняются `status`, `message`, `candidates`, `excluded`, `reason_counts`, `counts`, `evidence`, `warnings`, `calendar_window`. Статусы остаются `matched`, `no_category_in_city`, `no_matches`. Дополнительно возвращаются:

| Поле | Содержимое |
| --- | --- |
| `cards` | До трёх карточек после ранжирования всех допустимых кандидатов |
| `cards[].id`, `name`, `category`, `categories`, `city`, `price_from_kzt` | Поля для отображения |
| `cards[].synthetic`, `city_imputed`, `price_imputed` | Происхождение данных |
| `cards[].score`, `score_details` | Балл и объяснимая формула |
| `cards[].explanation` | 1–2 предложения с фактами и цитатой из описания |
| `cards[].evidence`, `warnings` | Поля-источники и предупреждения фильтрации |
| `ai.mode`, `ai.model`, `ai.message` | Фактически использованный способ ранжирования |

UI показывает `message`, карточки, пометки о синтетических профилях и `ai.message`. При пустой выдаче карточки пусты, но статус и объяснение причины сохраняются. Адаптер не создаёт страницу и не выполняет бронирование.

Низкоуровневые функции также доступны:

```python
from app.scorer import rank_contractors
from app.explainer import generate_explanation

ranked = rank_contractors(filtered["candidates"], filtered["request"],
                          preferences=request.get("preferences"), engine=engine)
for item in ranked[:3]:
    text = generate_explanation(item["contractor"], filtered["request"], item["score_details"])
```

## Формула и порядок

```text
semantic = max(0, cosine(query_embedding, description_embedding))
budget_headroom = 1 - price_from_kzt / budget
score = 70 × semantic + 30 × budget_headroom
order = (-score, id)
```

Смысловой компонент имеет больший вес, потому что отличает пожелания к стилю и содержанию работы. Запас бюджета — прозрачное предпочтение более доступной начальной цены; он не оценивает качество. Веса 70/30 — эвристика MVP, не обученная на оценках пользователей. При бюджете 0 допускается только бесплатный кандидат, его запас принимается равным 1.

Язык, формат и длительность уже прошли строгую проверку, поэтому одинаковые бонусы за них не добавляются. Итоговый балл округляется до 6 знаков и сортируется с постоянным `id` при равенстве. Исходный порядок CSV не влияет на выдачу. Ранжировщик повторно использует фильтр как проверку входного контракта и отклоняет передачу неподходящих кандидатов.

## Повторяемость, кэш и сбои

В корневом `.cache/embeddings.sqlite3` сохраняются векторы по модели и хэшу точного текста. В `.cache/ranking.sqlite3` сохраняется выбранный для конкретного CLI-запроса способ сравнения и значения сходства; сайт использует `.cache/web_preview_rankings.sqlite3`. Эти пути задаются в `app/paths.py` и не зависят от рабочей папки. Повторный запрос с теми же входными данными, настройками и сохранённым кэшем даёт тот же порядок даже после перезапуска и при недоступной сети. Перестановка исходного списка тоже ничего не меняет.

Первый результат fallback также фиксируется: восстановление API не меняет уже показанный ответ. Изменение пожеланий, профиля, модели, режима или версии алгоритма создаёт новую запись. Добавление ключа после запуска без ключа включает новую конфигурацию AI; замена одного ключа другим не обязана сбрасывать сохранённый fallback. Для намеренного пересчёта завершите приложение и переименуйте соответствующий файл `.cache/ranking.sqlite3` или `.cache/web_preview_rankings.sqlite3`; эмбеддинги можно сохранить. При недоступном для записи дисковом кэше приложение продолжит работу с кэшем текущего процесса, но сохранение между перезапусками не гарантируется.

Общий срок ожидания сетевого вызова — 6 секунд, включая DNS, заголовки и тело ответа; автоматических повторов нет. Тело читается порциями с проверкой срока. Запоздавший ответ не заменяет уже возвращённый fallback и не записывается в кэш эмбеддингов. Если нужных векторов нет в кэше, а API недоступен, ключ отсутствует или ответ некорректен, весь запрос переходит на сравнение слов с простым учётом русских окончаний; смешивания AI-баллов и fallback в одном запросе нет. Метаданные прямо указывают этот режим. Перед демо настоящее подключение нужно проверить с вашим ключом; сохранённые векторы позволяют использовать AI-результат без нового API-вызова.

Блокировка ранжирования действует только на одинаковые запросы. Разные параметры не создают очередь за медленным API. Сетевых операций в процессе не больше четырёх; если все слоты заняты, новый запрос сразу использует fallback. Зависший системный DNS нельзя принудительно отменить средствами стандартной библиотеки: до его завершения он занимает один из этих слотов, но не удерживает пользовательский ответ после истечения срока.

## Проверки и демо

```powershell
python -m unittest discover -s tests -v
python main.py recommend --offline --city Алматы --date 2026-09-23 --event-type свадьба --category Ведущий --budget 2000000 --preferences "интеллигентный юмор"
python main.py recommend --offline --city Алматы --date 2026-10-04 --event-type свадьба --category Флорист --budget 1000000
python main.py recommend --offline --city Алматы --date 2026-10-01 --event-type свадьба --category Ведущий --budget 1
python main.py recommend --offline --city Зарубежье --date 2026-10-04 --event-type свадьба --category Флорист --budget 1000000
python main.py recommend --offline --city Алматы --date 2026-10-01 --event-type свадьба --category Ведущий --budget 1000000
python main.py recommend --offline --city Алматы --date 2026-10-02 --event-type свадьба --category Ведущий --budget 1000000
```

Первые четыре запроса показывают ранжирование плотной категории, редкую категорию и два разных пустых исхода. Последние два показывают влияние календаря: 2 кандидата на 1 октября, 1 другой кандидат на 2 октября. В карточках указана дата из запроса, общая диагностика содержит исключения по занятости.

Тесты используют реальные 66 профилей и изолированный HTTP-макет OpenAI. Они проверяют правильный формат API, порядок векторов, кэш, ошибки сети, общий срок ожидания, параллельные запросы, влияние смыслового сходства на порядок, детерминизм, сохранение пожеланий, top-3 после полного ранжирования и фактологичность объяснений. `tests/test_web.py` проверяет HTTP-ответы сайта: дробную длительность, ошибки ввода, три исхода и сообщение о fallback. Настоящий API-запрос требует `OPENAI_API_KEY` и проверяется командой с `--require-ai`.

Стабильный порядок и кэш обеспечивают повторяемость. При сбое API пользователь видит, что применён запасной способ сравнения».
